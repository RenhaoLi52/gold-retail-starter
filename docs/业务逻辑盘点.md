# 业务逻辑盘点（截至 v0.26，2026-10-02）

依据：已交付的 26 个版本 + 用户提供的三份 JMP 真实导出（货品全生命周期 680 件×104列、权限矩阵 489 行、入库单模板 185 列）。

## 一、已完成的业务闭环

**货品与库存**：一物一码（大写字母+数字，唯一）；状态机 在库/已售/已退库 + 占用态 销售中/退库中/退货中/调拨中（约定：xx中=被未确认草稿占用）；位置维度 总库/分销商；stock_flow 只追加流水，每件货全程可回放（对应JMP导出里那一排"单号/时间/顺序"追溯列）。

**单据引擎（七种单据一套生命周期）**：RK入库 / TK退库(供应商) / XS销售 / XT销退 / DB调拨(分货·退回·互调) / PD盘点(三态对账快照) / HS旧料回收。共用：草稿→确认→反确认、挂单即锁定、条件更新并发裁决、单号发号器（前缀+日期+2位序号）、跨单据守卫（按件状态不按单据类型）。

**销售**：双模式（标签价/变金价）、议价留痕（参考价vs实售价）、金价快照（确认时刻）、组合收款（字典维护、合计分毫不差）、多售货员（1~3人平分）、以旧换新（换新价、金换金银换银额度、超出按回收、可倒付）、反确认限当日、跨日走销退（原单带出、退款≤原价、组合退款）。

**提成**：规则 大类×业务类型(正常/换新/回收)×结算方式，三种算法，版本化（valid from/to、排期、同日调整留痕、取消排期自动还原）；换新负规则=折扣；台账只追加（确认入账/反确认删除/销退负行冲减）；店长抽成（一店一店长，从店员份额中扣）；期间报表。

**账号与权限（现状）**：PBKDF2+JWT、禁用即时生效、账号绑门店（门店只见本店库存/单据、只办本店销售销退回收、总部职能403）、管理员标志、修改密码/重置密码。

**金价**：三价（零售/回收/换新）只追加发布、校验 回收≤换新≤零售。

**打印（方案1）**：标签数据导出，111列复刻 JMP↔Label Matrix 接口；销售凭证数据文件格式已破译待实现。

**桌面壳**：Electron 开发模式运行、登录态持久化。

## 二、缺口清单（按建议顺序）

### 1. 计价模型升级（销售正确性，最优先）⚠
JMP真实数据验证：按克货 **实售价 = 克重 ×（实售金价 + 每克销售工费)**（样例 BQ06552：2.46×(1169+78)=3068 ✓），工费也可按件（+固定额）。进货侧有 进货金价/进货工费 → 进货成本。
现状缺口：item 无 销售工费方式/销售工费、无 进货金价/进货工费；"变金价"建议价漏了工费。
要做：item 加四个字段；入库表单/Excel导入对应；变金价建议价改 克重×金价+工费；确认快照带工费明细；成本留底（将来毛利报表）。

### 2. Excel 批量入库导入（用户早期点名需求）
照"首饰入库单.xls"模板（185列，我们先吃核心列），全有或全无、停在出错行并报行号。顺带支持"条码前缀"列（JMP按前缀+号段发码，现自动发号规则可升级为 前缀可选）。

### 3. 角色与权限点框架
JMP矩阵：功能模块 ×（访问/查询/保存/新建/删除/修改/打印/确认/反确认/审核/反审核/标签/凭证）。
方案：角色表+角色权限点+账号挂角色；服务端每接口标权限点（现有 requireAdmin/requireHQ 升级为 requirePerm）；"修改销售日期"等特殊权限点并入。细粒度程度建议先做模块级（访问/操作/确认/反确认四档），用起来再细化。

### 4. 凭证打印
销售凭证套打数据文件（格式已在手：单据头50列+明细横铺+旧料/定金/赠品/优惠）→ Label Matrix/套打；质保单PDF（版面+打印预览，无打印机即可验收）。

### 5. 货品属性扩展 + 列模板 + 通用筛选器
JMP 还有：首饰类别(戒指/手镯…独立于名称)、首饰小类/系列/品牌、证书号×2、成色含量、主石副石配件、库位(柜组)、备注、自定义列。方案：常用列直接加（类别/证书号/库位/备注），长尾进 attrs JSONB；列模板（不同大类不同列）与通用筛选器（设计已定稿）一起做。

### 6. 旧料库
回收/换新收进来的料入台账（重量金额）、重炼出库、送供应商抵料。回收单确认时顺手写入，接口已留位。

### 7. 其他（已记录未排期）
会员/客户档案与积分（销售凭证含会员卡号/积分/折扣体系）；定金单；赠品；修改单（改货品属性留痕，JMP有修改单号）；月结锁定；分销商分组/柜组；迁移自动化（用户选择手动管理）；Electron打包分发；云端部署；数据迁移（本库数据导出格式已在手，680件样例可做导入演练）。

### 明确不做
借货/还货（用户确认无此习惯）。
